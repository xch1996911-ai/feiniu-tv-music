### 关于「退出登录显示不完整」的根因

旧实现把「logo + 7 个导航项 + 退出登录」塞进**同一个 `Column`**，
7 个导航项在 1080p 电视上必然超出可用高度 → `Column` 溢出，**底部退出登录被裁到屏幕外**。

现在改为三段式：`logo` / `Expanded(可滚动导航列表)` / `底部固定区`。
导航项再多也只是内部滚动，退出登录**永远完整可见**。第一次按 OK 不直接登出，
而是弹居中确认弹窗（`TvConfirmDialog`），确认后才调 `AuthRepository.logout()`。

### 关于「无风格标签」的如实显示

`genreOverviews()` 在曲目没有任何风格标签时**返回空列表**，页面显示
「暂无风格标签」——**不会**造一个「未知风格」出来。
（与之相对：歌手为空时确实存在「未知歌手」这个真实语义，所以那一条保留了。）

## 3. 数据来源与分组规则

| 维度 | 数据来源 | 分组规则 | 封面/头像 |
|---|---|---|---|
| 歌手 | `Track.artists[]` | 按**歌手 guid** 分组（`a:<guid>`），无 guid 时按归一化后的名字；`artists` 为空归「未知歌手」 | 取该歌手**第一首有封面的曲目**，在 `add` **之前**取（`setCoverIfEmpty`） |
| 专辑 | `Track.album` | 按**专辑名**分组（`al:<name>`）—— 飞牛的专辑对象没有稳定 guid 可用 | 同上 |
| 风格 | `Track.genre`/风格标签 | 按标签名分组（`g:<name>`）；**完全没有标签时返回空列表** | 用统一占位图标，不取曲目封面 |
| 统计口径 | 曲目数 `trackCount`、专辑数 `albumCount` | **由 Repository 层算**，UI 只负责显示 | — |

⚠️ 分组结果里的 `key`（`a:<guid>` 等）是**返回定位的唯一依据**。
用显示名做 key 会在「同名歌手/同名专辑」时定位到错误的位置。

## 4. 收藏 / 最近 / 偏好的存储方式

全部走 `lib/services/secure_store.dart`（`flutter_secure_storage`，不引入 `shared_preferences`）：

| 键 | 内容 | 写入时机 |
|---|---|---|
| `feiniu.favorites.guids` | 收藏的曲目 guid 列表 | `toggleFavorite()` 先改内存后落盘 |
| `feiniu.favorites.seeded` | 「是否已从服务端播种过」的**独立标记** | `seedFavoritesIfNeeded()` 只播种一次 |
| `feiniu.recent.guids` | 实际播放过的 guid（倒序、上限 50、去重） | 每次 `recordPlayed()` |
| `feiniu.playerlayout` | `'stage'` / `'cover'` **字符串**（刻意不用 index） | 切换版式时 |

⚠️ 两个刻意的设计决定：

1. **收藏用独立数据源，不读服务端 `Track.isFavorite`。**
   飞牛**没有收藏写接口** → 服务端字段永远是你本地那份的旧副本。
   播种只在「曲库非空 **且** 未播种过」时做一次，并用**独立的 seeded 键**记录 ——
   这样即使用户把收藏**全删空**，也不会下次启动又被播种回来。
2. **偏好值存字符串不存 index。** 枚举顺序将来一变，存 index 就会把
   「stage」读成「cover」，属于静默数据损坏。

## 5. 在线歌词服务及其限制

### 三段式

```
① NAS   GET /lyric/list?trackGUID=<guid>   上限 12s  非空即用
② 在线  LRCLIB https://lrclib.net/api      上限 9s   仅当 ① 为空/失败
③ 都没有 → 空歌词 + 保留 ① 的错误信息
```

### 服务：LRCLIB（<https://lrclib.net>）

**选它的首要理由是免密钥** —— 需求明确要求「密钥不得硬编码/提交/写日志」，
免密钥从根上消除这个风险。请求头只带一个用于标识客户端的 `User-Agent`，
**每次请求显式带上**（写在自建 Dio 的 `BaseOptions` 里会在注入外部 client 时丢失）。

### 打分规则（`OnlineLyricMatcher`，纯函数、可单测）

| 维度 | 条件 | 得分 |
|---|---|---|
| 标题 | 完全相同 | +0.55 |
| | 一方包含另一方 | +0.35 |
| | **都不沾边** | **直接 return 0**（不再看歌手与时长） |
| 歌手 | 完全相同 | +0.30 |
| | 一方包含另一方 | +0.18 |
| | 都不同 | −0.15 |
| | 任一方缺失 | +0.15 |
| 时长 | 差 ≤3s / ≤10s / >30s | +0.20 / +0.10 / −0.20 |

归一化会去掉括号内容（`(Remastered)`、`[Live]`）、`feat./ft./with` 等版本词，
以及全部非字母数字汉字；歌手名只取第一个（`A feat. B` → `A`）。
最后 `clamp(0, 1)`。

**只有 ≥ `acceptThreshold = 0.7` 才自动绑定**；不足阈值时**只把候选列出来交给用户手动选**，
绝不猜。⚠️ 打分与阈值判定**由 `LyricRepository` 自己做**，不信任来源给的 `score` ——
否则换一个不打分/不排序的来源实现，就会静默退化成「永远只列候选、从不自动绑定」。

### 限制（如实列出）

1. **LRCLIB 是第三方公共服务**：可用性、限流、数据覆盖都不由本项目控制。
   它是**兜底**不是依赖 —— 它挂了最多是「没有在线歌词」，不影响播放。
2. **只匹配到「歌名 + 歌手 + 时长」这一层**：现场版、翻唱、纯音乐等
   会因为时长/标题差异得分不足而**只成为候选**，需要用户手动选一次。
3. **中文件曲的覆盖率明显低于英文**，LRCLIB 的曲库以西方流行/摇滚为主。
4. **按需联网，不做后台预取**；断网时静默降级到 NAS 结果或空歌词。
5. 候选列表目前**没有做持久化**（换歌即失效），也没有「记住这次的手动选择」的
   长期记忆 —— 下次放同一首仍会重新匹配。
6. ⚠️ **在线匹配这条链路只在 CI 的单元测试里验证过**，
   **没有在电视上真实联网测过**（含 NAS 无歌词 → 触发在线 → 匹配成功/失败的真实时序）。

## 6. 本轮修掉的 CI 故障（30 → 5 → 0）

### 第 1 轮：`analyze` 16 条问题（`8e12b9a` → `bebbf3c`）

+ 3 条 `expected_token`），外加测试里 2 条 `instance_access_to_static_member`。
其余是 `prefer_const_declarations` / `unused_element_parameter` / `prefer_const_constructors`。

### 第 2 轮：`flutter test` 302 通过 / 30 失败（`bebbf3c` → `1d26237`）

四条**真 bug**（都会在电视上犯）+ 三条**测试自己写错**：

| 类型 | 根因 | 修复 |
|---|---|---|
| 真 bug | `player_page.dart`：`context.select` 被 `LayoutBuilder` 的 builder **间接调用** —— builder 跑在 **layout 阶段**（`debugDoingBuild == false`），provider 断言直接抛异常。**13 条用例**全挂在这一个根因上 | 在真正的 `build()` 里读好再当参数传下去 |
| 真 bug | `overview_page.dart`：M3 主题的 `DefaultTextStyle` 行高是 **1.43**（不是 1.0），固定行高里「21px 标题 + 15px 副标题」实际占 55.5px、可用只有 50px | 行内 Text 全部显式 `height:`；行高按真实占位反算；专辑瓦片行高**由封面宽度反推** |
| 真 bug | `lyric_repository.dart` 信了来源给的 `score` 与「第一条即最佳」 | 本层用同一个打分器重算 + 阈值判定 |
| 真 bug | `LrclibLyricSource` 的 `User-Agent` 只在自建 Dio 的 `BaseOptions` 里，注入外部 Dio 时丢失 | 每次请求显式 `Options(headers: ...)` |
| 测试错 | `tr()` 里 `artistGuid` 默认「每首歌一个歌手」，用例本意是「同一歌手多首歌」 | 用例显式传同一个 guid |
| 测试错 | `TvFocus.debugLabel` **只在自建节点时生效**，外部节点用 `FocusNode` 自己的标签 | 改用节点标签；删掉永不生效的那份 |
| 测试错 | 孙燕姿有两张专辑、副标题相同，`findsOneWidget` 写错 | `findsNWidgets(2)` |

### 第 3 轮：只剩 5 条（`1d26237` → `9323069`）

**全部与业务逻辑无关**，是两类行高精度问题：

| 位置 | 现象 | 根因 | 修复 |
|---|---|---|---|
| `queue_sheet.dart`（3 条用例） | `overflowed by 2.0 pixels`（可用 46px） | 两个 `Text` 没写 `height` → 继承 1.43：`26 + 2 + 20 = 48` | 加 `height: _textHeight`(1.2) → `22 + 2 + 17 = 41` |
| `overview_page.dart`（2 条用例） | `overflowed by 0.400 pixels` | ⚠️ **写了 `height` 也红**：Flutter 把**每一行**的行盒高度**向上取整**，`19×1.2=22.8→23`、`14×1.2=16.8→17`，算式上「刚好等于行高」被判溢出 0.4（0.2+0.2） | 标题 19→**20**、副标题 14→**15**（乘积变整数 24/18），再加 `slack = 2` |

**新沉淀的规则**（已写进常量定义处、`MEMORY.md` 和技能库）：

1. 固定行高里的 `Text` **必须显式写 `height`**（M3 默认 1.43）；
2. **`字号 × height` 必须是整数** —— Flutter 逐行向上取整，
   「算术上刚好相等」会被判溢出，肉眼绝对看不出来；
3. 同一个量只允许有一处定义（行高倍数收敛成语义化常量 `_textHeight`）。

### 建议的下一步

装上 `app-hisense-release.apk`，按这个顺序看：

1. 启动 → 登录 → 首页是否正常出画面（首页这一层上一轮已实机验证过）；
2. **概览页**：进「歌手」→ 点一个歌手 → 返回，**看是否回到原来那一格**；

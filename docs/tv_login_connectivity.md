# 电视端「登录一直显示连接中」排错

实机环境：海信 E7N Pro / VIDDA，Android TV，**无 adb**。
现象：焦点修复后成功进入登录页，填好地址 / 用户名 / 密码，点「连接并登录」，
界面**永远停在「连接中…」**，既不成功也不报错。

---

## 一、为什么「停在连接中」比「报错」更难查

电视上没有 adb，也没有 `flutter run`。屏幕和 `boot.log` 是仅有的两个信息出口，
而这两种失败在屏幕上长得一模一样：

| 实际发生的事 | 屏幕表现 |
|---|---|
| 请求发出去了，服务端报错（凭据错、路径错） | 有错误文字 ✅ 可查 |
| 请求根本没发出去（地址格式错） | 卡在「连接中」❌ |
| 请求发出去了，但服务端永不回应 | 卡在「连接中」❌ |
| 请求成功了，却卡在**写安全存储** | 卡在「连接中」❌ |

所以排查思路是：**先把「可能是哪个环节」变成「屏幕上能读出来的事实」**。

## 二、根因一：地址漏写 `http://`（真实故障）

用户在遥控器上输入 `192.168.3.250:5666` —— 地址栏 hint 里写的是
`http://192.168.1.10:5666`，但遥控器输入不会照抄 hint。

`FnosClient` 原先把用户输入**原样**交给 Dio 作 `baseUrl`，于是请求 URL 没有 scheme，
请求发不出去（或被判成相对地址），界面停在「连接中」，且没有任何有意义的错误。

**修法**：`FnosClient.normalizeBaseUrl()`

- 用 `^[a-zA-Z][a-zA-Z0-9+.\-]*://` 判定是否已有 scheme ——
  ⚠️ 判定必须**要求字母开头**。写成 `^[^/]+://` 之类会把 `192.168.3.250:5666`
  里的冒号误判成 scheme 分隔符，等于没修。
- 无 scheme → 补 `http://`（局域网 HTTP 5666 是绝对主流）。
- 去掉尾斜杠，否则端点路径自带的前导 `/` 会拼成 `//music/api/v1`。
- 归一化做在**构造函数里**，因此登录、恢复会话、探针三条入口全部覆盖。

## 三、根因二：「不返回也不抛异常」的三个挂起点

这条路径上有一类失败是 `try/catch` 抓不住的 —— **Future 永不完成**。
三个位置都要各自限时：

| 位置 | 为什么会挂 | 上限 |
|---|---|---|
| `SecureStore.getOrCreateDeviceId()` | 内含 MethodChannel 调用；通道对端不回应时 `invokeMethod` 永不完成 | 8s |
| `FnosProvider.login()` | Dio 的 `receiveTimeout` 只约束**两个数据包之间的间隔**，服务端持续吐字节但永不结束时不触发 | 40s |
| `SecureStore.saveSession()` | **登录其实已经成功**，却卡在写安全存储；`login()` 返回前不会调 `onLoggedIn`，界面同样停在「连接中」 | 8s |

另外 `BootLog.nativeDeviceId()` 本身也补了 5s 超时：它排在
`getOrCreateDeviceId()` 的第一步，通道卡住时同样会让登录无限等待。

> `saveSession` 超时**不算失败**：内存里的 provider 已经可用，本次登录照常生效，
> 只是下次启动需要重新登录。绝不能因为存储问题把已登录成功的用户挡在门外。

## 四、把诊断做进屏幕（本轮的关键）

新增 / 改动都在 UI 层，登录页现在会显示：

1. **当前阶段**：`读取设备标识… / 请求登录… / 保存会话…` —— 直接指出卡在哪一步；
2. **已等待秒数**：区分「网络慢」与「永久挂起」；
3. **实际请求地址**（归一化后）—— 地址写错时一眼可见；
4. **错误原始信息**：`kind=` + `cause`，不用猜是网络、凭据还是解析问题；
5. **「只测试连接（不需账号和密码）」按钮** —— 请求免鉴权的
   `initialization/state`，把「地址 / 网络不通」与「凭据不对」彻底分开。

按钮的 hint 也改成 `192.168.1.10:5666`（不带 scheme）+ 一行
「漏写 http:// 也没关系，会自动补上」，避免继续误导用户。

## 五、屏幕判读表

按下「连接并登录」后，

| 屏幕显示 | 结论 |
|---|---|
| 阶段停在**读取设备标识**，等到超时 | 安全存储 / 原生通道问题，与网络无关 |
| 阶段停在**请求登录**，等到超时（40s） | 地址或网络不通（用探针按钮复核） |
| 阶段停在**保存会话** | 登录已成功，是安全存储写入慢/挂；本次仍可用 |
| 出现红色错误 + `kind=auth` | 凭据错误（120001），改用户名 / 密码 |
| 出现红色错误 + `kind=network` | 网络不可达 / 地址错 |
| 出现绿色「连通正常」 | 地址与网络没问题 → 问题在凭据或后续链路 |

## 六、回归测试

- `test/fnos_client_url_test.dart`：`normalizeBaseUrl` 的 6 条
  （补 scheme、不改写已有 scheme、去尾斜杠、IP 冒号不被误判、空串、构造时归一化）。
- `test/auth_repository_probe_test.dart`：断言探针发出的是**带 scheme 的绝对 URL**
  （`scheme=http`、`host=192.168.3.250`、`port=5666`、路径正确）——
  这条测试就是为了钉死本轮这个 bug，防止以后有人把归一化删掉。
